DATABASE CHANGES REQUIRED FOR ROLE-BASED SYSTEM

1. USERS/BROKERS TABLE UPDATES:
   - Add a new column named `role` to the database table that stores user/broker information.
   - Type: ENUM or String.
   - Allowed values: 'SUPERADMIN', 'ADMIN', 'OFFICE', 'ASSOCIATE'.
   - Default value: 'ASSOCIATE'.

2. NEW API ENDPOINTS REQUIRED (Protected by JWT & Role Middleware):

   A. SUPER ADMIN APIs (Accessible only by role 'SUPERADMIN'):
      - GET /broker/superadmin/users -> Returns a list of users with roles 'ADMIN' and 'OFFICE'.
      - POST /broker/superadmin/users -> Creates a new user. Request body must include `role` (either 'ADMIN' or 'OFFICE') along with standard registration fields.
      - DELETE /broker/superadmin/users/{id} -> Deletes an admin or office member by ID.

   B. ADMIN APIs (Accessible only by roles 'SUPERADMIN' and 'ADMIN'):
      - POST /broker/admin/users -> Creates a new user with the role 'OFFICE'.

   C. OFFICE APIs (Accessible only by roles 'SUPERADMIN', 'ADMIN', and 'OFFICE'):
      - GET /broker/office/associates -> Returns a list of users with the role 'ASSOCIATE' (brokers).
      - POST /broker/office/associates -> Creates a new user with the role 'ASSOCIATE'.
      - DELETE /broker/office/associates/{id} -> Deletes an associate by ID.

3. LOGIN / ME ENDPOINT UPDATES:
   - Ensure that the `/broker/me` and `/broker/login` endpoints return the `role` field in the response JSON so the frontend can route the user to the correct dashboard panel upon successful authentication.

4. ANNOUNCEMENTS TABLE & APIs:
   - Create an `Announcements` table (id, title, content, target_role ['ADMIN', 'OFFICE', 'ALL'], created_by, created_at).
   - POST /broker/announcements -> (SuperAdmin only) Create an announcement.
   - GET /broker/announcements -> Returns announcements visible to the logged-in user's role.

5. PROFILE MANAGEMENT APIs:
   - PUT /broker/me -> Updates the logged-in user's profile (name, etc.). Referral code should be read-only for the user.
